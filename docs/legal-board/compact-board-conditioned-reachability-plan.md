# 소형 보드 조건부 도달성 기반 BuildUp 가속 기획

> 작성일: 2026-09-22
> 상태: 사용자 정정을 반영한 연구·설계 제안. 구현, 자산 생성, GPU 실행, 성능 A/B는 수행하지 않았다.
> 기준 소스: `dbc2140213214f96f8c705a5237441dc008ca5c2`.
> 관련 문서: [문제 대장](build-up-acceleration-issue-register.md), [검증 계획](build-up-acceleration-validation-plan.md), [기존 비교 기록](wirelyre-clearra-differences.md).

## 1. 결정과 비목표

주 병목은 구축 검증(BuildUp)이라는 사용자 관측을 기획의 기준으로 삼는다.
Inverse Lock-Clear(ILC)와 APDP의 기하 후보 생성은 유지한다.
Geometry만 빨라진 결과를 BuildUp 가속의 근거로 보고하지 않는다.

사전 생성은 배포 전에 오래 수행할 수 있고, 그 시간은 사용자 실행 시간에서 제외한다.
그러나 전송량·설치량·디코딩 비용·실행 중 메모리는 계속 제한한다.
사용자는 현재 PC4 TB 약 600MB도 커서 온라인 조회 전용으로 바꾸었다고 설명했다.
이 크기와 운용 상태는 사용자 제공 맥락이며 이번 작업에서 다운로드·실측하지 않았다.

따라서 다음을 주력안에서 제외한다.

| 제외하는 안 | 이유 |
| --- | --- |
| 모든 보드 × 7미노 × 모든 reachable lock 전량 배포 | GB급 TB를 다시 만드는 결과를 허용하지 않음 |
| 모든 도면의 BuildOrder 그래프·언어를 무제한 사전 저장 | 후보 수와 그래프 크기에 따른 총량을 제한하지 못함 |
| 큰 TB를 작은 조각으로 나눈 것만으로 소형화라고 보고 | 한 실행·세션에서 결국 대량 다운로드하면 같은 문제 |
| PC4 온라인 TB를 새 가속기의 필수 의존성으로 연결 | 기존 온라인 전용 제품과 별도의 소형 가속이라는 목적이 달라짐 |
| 회전 프로필별 특정 킥 결과만 저장 | 실제 회전 성공과 도달 위치는 주변 보드 조건에 의존 |
| 고정된 작은 창만 보고 전체 spawn-to-lock을 단정 | 입구까지의 경로와 창 밖 장애물 영향이 누락될 수 있음 |

정확한 MB 상한은 아직 합의되지 않았다. 임의의 수치를 사용자 승인 한도로 만들지 않는다.
구현 채택 전에 총 배포량, 요청당 수신량, 세션 누적 수신량, 디코딩 peak,
상주 메모리 및 worker별 복제량의 예산을 명시해야 한다.
소형화가 실제로 확인되지 않으면 다운로드 방식을 바꾸어 승격하지 않는다.

## 2. 출처와 확인 수준

### 2.1. 소스에서 확인한 현재 구조

- `ReachabilityTemplate`은 미노·회전 프로필·보드 크기로 가능한 pose와 전이 후보를 컴파일한다.
- `first_successful_kick()`는 해당 보드와 충돌하지 않는 **첫 번째** 회전 후보를 선택한다.
- `reverse_lock_reachable()` 계열도 정방향 후보의 우선순위 제약을 보존해야 한다.
- `ReachabilityWorkspace`에는 하드드롭 단축 경로와 질의 내 정확 캐시가 이미 있다.
- 일반 커버리지 경로는 후보별 `BuildOrderGraph::build()` 후 구축 언어를 정규화하고 공급·홀드와 결합한다.
- 따라서 단순히 킥 오프셋을 미리 배열로 만들거나 캐시를 하나 더 추가하는 것은 신규 효과가 아니다.

근거: [reachability.rs][reach], [buildup.rs][build], [catalog.rs][catalog].
해당 함수 존재와 제어 흐름을 확인한 것이며 각 단계의 실제 시간 비중은 새로 계측하지 않았다.

### 2.2. 사용자 요구

- ILC와 APDP는 사용자 개발 알고리즘이다. 외부 알고리즘의 재명명으로 취급하지 않는다.
- 사전 생성 시간이 아니라 런타임 BuildUp 병목을 줄이는 것이 목적이다.
- WASM과 분리된 작은 자산을 필요 시 내려받는 구조는 허용한다.
- 기존 약 600MB TB와 같은 문제를 반복하는 대형 자산은 허용하지 않는다.
- 저장 대상은 주변 보드 상태에 따른 도달 위치 변화다.

### 2.3. 아래의 새 설계

조건부 전이, 국소 입출구 도달 관계, 보드 변화에 대한 증분 재계산은 실험 후보다.
압축률, 완전성 증명 범위, 속도 개선은 아직 확인되지 않았다.
외부 Wirelyre 소스·생성 자산을 복사하거나 의존성으로 추가하는 계획이 아니다.

## 3. 킥 후보, 실제 전이, 전체 도달성을 구분한다

킥테이블의 오프셋 순서는 선택한 프로필과 미노·회전 전이에 의해 정해진다.
주변 보드는 그 후보들 중 어느 것이 처음으로 성공하는지 바꾼다.
따라서 고정된 후보 목록과 보드에 조건부인 실제 전이를 같은 것으로 설명하지 않는다.

source pose를 `p`, 회전 요청을 `a`, 순서 있는 후보를 `t_0 ... t_n`이라 하면,
보드 `B`에서 후보 `i`가 실제 전이가 되는 조건은 다음과 같다.

```text
source가 유효함
AND t_i가 경계 안에 있고 B와 충돌하지 않음
AND 모든 j < i에 대해 t_j가 경계 밖이거나 B와 충돌함
```

앞선 후보가 이미 성공하면 뒤의 후보가 비어 있어도 직접 선택할 수 없다.
역방향 질의에서도 오프셋 부호만 뒤집지 않고, 정방향 source의 이 조건을 보존한다.

전체 도달성은 이런 보드 조건부 전이를 이어서 시작 자세 집합에서 도달하는
pose/lock들의 집합이다. 한 번의 회전 성공, 국소 경로 존재, 전체 lock 도달은 다르다.

스핀 역시 reachable lock 하나만으로 확정하지 않는다. 출력 계약에 따라
마지막 행동, 회전 방향, kick index, first-success, 코너·immobility 등의 증거가 필요하다.
단순 도달성 가속 기록은 스핀/B2B/점수의 완전한 증거를 대신하지 않는다.

## 4. 저장 대상: 보드 조건부 도달 관계

가칭은 `BoardConditionedReachability`로 한다. 이름은 구현 확정 명칭이 아니다.
전체 보드마다 결과를 하나씩 보관하기보다, 같은 도달 관계를 만드는 조건을 공유한다.

### 4.1. 질의 계약

| 입력 | 의미 |
| --- | --- |
| 실제 compacted board | ILC 논리 셀 소유권 마스크와 구분한 물리 상태 |
| 미노·회전/이동 규칙 identity | 후보 순서, shape 원점, 180 지원, 경계·lock 의미 포함 |
| 시작 또는 진입 pose 집합 | 전역에서 실제 도달한 상태만 입력 |
| 의존 셀의 점유 조건 | 해당 관계의 전이를 바꿀 수 있는 모든 셀 |
| 벽·바닥·상단·좌표 frame | 동일한 모양의 창이어도 경계 조건이 다름 |
| 목표 lock 또는 질의 범위 | 목표 하나의 도달성과 전체 도달 집합을 구분 |
| 필요한 증거 종류 | Boolean reachability와 spin/finesse/CountAll을 구분 |

출력은 가능한 경우 다음 중 하나다.

- 검증된 조건에서의 정확한 `진입 pose → 출구 pose / 국소 lock` 관계.
- 전역에서 도달한 진입 pose로부터 복원 가능한 도달 witness 또는 macro 전이.
- 명시한 폐쇄 범위 내에서의 검증된 도달 불가능.
- `Unknown / OutOfScope / NotLoaded / InvalidAsset`: 기존 정확 탐색으로 진행.

국소 관계의 부정 결과만으로 다른 진입점·창 밖 우회 경로까지 불가능하다고 하지 않는다.

### 4.2. '주변'은 고정 크기 사각형을 뜻하지 않는다

한 단계의 충돌 의존 영역은 source, 이동 목적지, **앞선 킥 후보를 포함한 모든 검사 pose**,
바닥 접촉과 경계 판정에 필요한 셀에서 계산한다.
멀티스텝 macro는 그 내부 모든 검사 의존 영역의 합을 사용한다.

지정한 창 밖의 후보가 first-success를 바꿀 수 있다면 halo/경계 서명에 포함하거나
그 질의를 지원 범위 밖으로 처리한다. 일부 셀만 보고 안전하다고 가정하지 않는다.

같은 서명으로 묶인 모든 보드에서 해당 **국소 관계**가 같다는 것을 검증해야 한다.
이 등가성은 전체 보드의 spawn-to-lock 결과까지 같다는 뜻이 아니다.
필요 의존 영역이 너무 커지면 작은 자산으로 처리하지 않고 일반 탐색으로 돌아간다.

### 4.3. 진입·출구 관계로 전역 경로를 합성한다

국소 블록은 동일한 실제 보드 스냅샷에서, 명시된 pose 영역 내부의 경로를 요약한다.
전역 탐색이 증명한 진입 pose를 적용하여 출구와 내부 lock을 얻고,
다른 블록 또는 일반 전이와 연결한다. ILC가 요구한 목표 lock을 찾으면 해당 질의를 끝낸다.

국소 영역 밖으로 나갔다 돌아오는 경로는 전역 연결 단계가 보존한다.
후보 전체의 UNSAT나 모든 lock의 불가능을 선언하려면 모든 가능한 경계 연결이
소진되었거나 동등한 완전성 증거가 있어야 한다.

macro가 회전/이동 경로를 여러 개 합칠 때 Boolean 도달성만 보존할 수 있다.
경로 개수나 스핀 증거가 필요한 모드에서는 다중 경로 의미를 보존한 별도 기록이
있어야 하며, 없으면 기존 해당 모드의 정확한 경로를 사용한다.

## 5. 소형화 후보와 한계

### 5.1. 조건식과 공유 결정 그래프

first-success 조건은 `목적지 footprint가 비어 있음`과
`앞선 후보 footprint마다 적어도 하나의 장애물이 있음`의 조합으로 표현할 수 있다.
뒤 조건은 footprint 전체가 차 있다는 뜻이 아니다.

반복되는 충돌 mask와 Boolean 조건을 공유하고, 조건부 관계를 결정 DAG나
작은 사전의 참조로 기록하는 방식을 실험한다. 이것은 모든 점유 조합을 무조건
`2^b`개 행으로 저장하겠다는 계획이 아니다.

단일 킥 결과만 작은 표로 바꾸면 이미 짧은 현재 루프보다 느릴 수 있다.
성능 목표는 반복 이동·킥 검사를 묶은 관계나 반복되는 부분 경로를 생략하는 것이다.
조건 추출·서명 생성·조회 비용을 포함해 측정한다.

### 5.2. 제한된 국소 macro 관계

예산 안에서 압축 효과가 있는 영역·진입 인터페이스만 사전 계산한다.
부모 보드·도면과 무관하게 재사용되는 관계를 우선하고, 각 기록의 압축 후 크기와
실제 적용 범위를 보고한다. 작은 영역도 가능한 입출구 관계가 많으면 커질 수 있다.

부분 영역을 대칭화할 때 좌우 미노 교환, 회전 방향, ordered kick, 경계 조건의
대칭까지 확인한다. 시각적으로 같은 모양이라는 이유만으로 물리 관계를 합치지 않는다.

### 5.3. 작은 정확 캐시와 증분 적용

완전한 동일 키의 최근 질의는 bounded cache로 재사용할 수 있다.
보드가 바뀌면 변경 셀과 겹치는 전이 조건을 무효화하고 영향 범위를 다시 계산하는
방식도 실험할 수 있다. 다만 이는 신규 실험이지 현재 캐시에 없는 기능이라고
성능상 단정하는 것은 아니다.

장애물을 추가하면 앞선 킥이 막혀 뒤 킥이 선택될 수 있다. 따라서 실제 first-success
도달 집합은 단순히 장애물 수에 대해 단조 감소한다고 가정할 수 없다.
삭제·추가 delta 양쪽을 고려하고, 순환과 대체 경로가 있는 그래프의 도달성을
변경된 인접 간선만 지우는 수준으로 갱신하지 않는다.
줄 삭제는 많은 셀과 좌표를 바꾸므로 이전 서명/캐시를 그대로 유지하지 않는다.

### 5.4. 확정하지 않는 것

- 작은 창으로 모든 보드의 정확 도달성을 해결할 수 있다는 주장.
- BDD/사전화로 최종 자산이 특정 MB 이하가 된다는 주장.
- 전체 도면 언어를 사전 저장해도 충분히 작다는 주장.
- 사용자 보드에서 높은 적중률·기존보다 빠른 속도가 나온다는 주장.

이 항목은 생성 후 크기와 동일 조건 A/B가 있어야 판단한다.

## 6. ILC / APDP / BuildUp 연결

ILC는 목표 프레임의 배치와 시간적 실현을 생성하고, APDP는 그 도메인을 좁힌다.
BuildUp의 `CandidateProjection`이 부분집합에서 실제 보드·삭제 행을 구하고,
카탈로그가 논리 배치를 실제 lock 좌표로 변환한다.
소형 도달성 관계는 **그 물리 질의 지점**에 들어간다.

```text
ILC / APDP 후보
→ CandidateProjection: 물리 board + 원래 deleted-row map
→ 요구 배치의 실제 lock 좌표
→ 기존의 싼 하드드롭/정확 캐시 또는 소형 조건부 관계
→ 미지원/미적중이면 기존 reachability
→ BuildOrderGraph
→ 공급·홀드 언어 결합
→ 원본 도면 ID별 Coverage
```

하드드롭·현재 캐시·새 관계 중 어느 것을 먼저 적용할지는 비용 A/B로 정한다.
새 lookup을 붙였다는 이유만으로 그래프 생성 비용까지 제거되었다고 보고하지 않는다.

현재 구축 언어 정규화·캐시는 그래프 생성 뒤에 있으므로, 언어 hit가 앞의 BuildUp
전체 생략을 뜻하지 않는다. 전체 언어 TB를 만들지는 않는다. 그래프 생성이 여전히
주요 비용이면 범위가 제한된 요청 내 공유나 작은 macro의 간선 생성 효과를 별도로 연구한다.

PC 전용 co-reachability와 목표 독립적인 물리 reachability를 섞지 않는다.
일반 구축 확률·경계 커버리지의 중간 상태를 PC 불가라는 이유만으로 제거하지 않는다.

## 7. 작은 자산의 lazy 배포 계약

WASM과 자산은 분리할 수 있다. 그러나 작은 shard의 합이 수백 MB/GB인 자동 다운로드로
귀결되면 이번 요구를 만족한 것으로 보지 않는다. 기존 PC4 TB의 온라인 전용 정책도 바꾸지 않는다.

배포 manifest에는 다음을 포함한다.

- immutable generation, schema, 정규화·규칙·도달 의미 fingerprint.
- 전체 자산과 선택 profile pack의 압축 크기, 각 블록의 해제 크기 및 디코더 한도.
- 지원 영역·경계/진입 의미·출력 증거 수준·완전성 범위.
- 각 블록과 인덱스의 digest 및 안전한 참조 범위.

host가 수신과 캐시를 소유하고 solver hot loop는 HTTP를 호출하지 않는다.
한 질의마다 네트워크 왕복하는 대신 작은 pack을 재사용한다.
필수 pack을 받지 못했거나 크기 예산을 넘으면 기존 계산을 사용한다.
캐시된 요청은 계속 정확해야 하고, cache eviction은 불가능 판정이 아니라 miss다.

한 실행에서 generation을 고정한다. CDN에서 manifest와 payload의 세대가 섞이면
해당 자산을 거절한다. 개발 시 branch 조회에는 cache 구분을 사용할 수 있지만,
제품 캐시는 내용 기반 identity를 사용하고 매번 랜덤 URL로 재사용을 파괴하지 않는다.

원격 자산이 검증되지 않았으면 데이터 사용은 중단하고 기준 solver로 진행한다.
이미 잘못된 데이터로 prune한 사실이 발견되면 결과를 그대로 반환하지 말고 해당 작업을
기준 경로에서 다시 계산한다. 자산 해시는 내용 무결성이지 의미적 정확성의 증명 자체가 아니다.

## 8. 평가·채택

생성 시간은 별도 기록만 하고 런타임 비교에서 제외한다.
하지만 콜드 다운로드, 압축 해제, 여러 worker의 복제, 세션 누적 수신은 포함한다.

비교군은 기존 코드, 같은 compact 표현의 CPU 참조, 조건부 전이, 국소 macro,
둘의 결합을 분리한다. 동일 입력·규칙·출력 계약·완료 종점을 사용한다.

필수 성과는 다음 두 조건을 모두 만족하는 것이다.

1. 명시된 소형 자산/실행 메모리 예산 안에서 동작함.
2. 실제 BuildUp 또는 제품 전체 실행을 정확한 결과 보존 아래 가속함.

노드 처리율이나 크기 감소만으로 채택하지 않는다. 저장 행렬의 최소화 시간을
Geometry/BuildUp 가속 시간과 섞지 않는다. 새 성능 수치와 압축률은 아직 없다.
구체적 절차는 [검증 및 A/B 계획](build-up-acceleration-validation-plan.md)을 따른다.
