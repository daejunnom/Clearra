## 최신 기획의 고정 전제

- 주 가속 대상은 Geometry가 아니라 **구축 검증(BuildUp)** 이다. Inverse Lock-Clear와 APDP의 역할은 유지한다.
- 사전 생성 시간은 사용자 실행 시간과 분리한다. 생성 비용이 크다는 이유만으로 후보를 배제하지 않는다.
- 그러나 생성 비용을 제외한다는 말은 **배포 용량·다운로드·디코딩·상주 메모리를 무시한다는 뜻이 아니다**.
- 사용자는 기존 PC4 TB가 약 600MB여서 온라인 조회 전용으로 전환했다고 설명했다. 이 수치는 사용자 제공 맥락이며 이번 문서 작업의 신규 자산 실측값이 아니다.
- GB급 전체 보드별 배치 TB 또는 도면별 구축 언어의 전량 배포를 주력안으로 채택하지 않는다. 작은 파일들로 나누어 같은 대용량을 결국 전부 받는 방식도 해결책이 아니다.
- 사전 계산 대상은 고정된 특정 킥의 결과가 아니라 **주변 점유·벽·바닥·입구 자세에 따라 달라지는 도달 위치/자세 관계**다. 킥 후보 순서와 보드 조건에 의해 선택된 실제 전이를 구분한다.
- 국소 관계가 전체 spawn-to-lock 도달성이나 스핀 판정을 자동으로 증명하지 않는다. 범위를 벗어나거나 데이터가 없으면 기존 정확 경로로 돌아간다.
