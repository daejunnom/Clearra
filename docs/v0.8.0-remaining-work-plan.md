# Clearra v0.8.0 남은 작업 통합 구현·활성화·배포 계획

## 1. 권위, 범위, 시작 ledger

이 문서는 v0.8.0에 남은 작업의 단일 실행 계획이다. 저장소 루트의
`Clearra 핸드오프.md`가 더 높은 설계 권위이며, 이 문서는 그 문서를
변경하거나 구현 완료 증거로 대체하지 않는다. 충돌 시 권위 순서는
`Clearra 핸드오프.md` → 기능별 규범 문서 → contract fixture/test → source →
pinned 외부 비교 자료다.

구현 시작 기준은 2026-08-27의 `codex/v0.8.0`,
`042ec210d206ba81e2eccbe70ca629c3bef22d0d`이다. 시작 worktree의 기존 dirty
변경은 모두 보존한다. 최종 acceptance는 별도의 clean release worktree에서
exact candidate SHA로 수행한다.

계약 정규화 직후 구현 시작 ledger는 정확히 다음 49 blockers다.

| 구분 | 열린 행 |
| --- | ---: |
| capability | 38 |
| result-affecting option | 4 |
| accepted requirement | 7 |
| 합계 | **49** |

기존 46개에 다음 변경을 적용한다.

- 이미지 인식 `utility.to-fumen` capability와 implementation/planned projection을
  삭제하고 `sfinder-man/tofumen`, `sfinder-man/calibrate`를 명시적 exclusion으로
  재분류한다. native typed Fumen codec/output은 삭제 대상이 아니다.

## 2. `REQ-V080-021`: exact portfolio alternatives

### 2.1 적용 단위와 대표 metric

Tie는 여러 하위 해법으로 이루어진 서로 대체 가능한 최적 **portfolio**가
여러 개일 때만 성립한다. 내부 replay, trace, cell, contribution의 동률이나
정상 witness/solution family는 public portfolio tie가 아니다.

Probability나 score 같은 선행 조건으로 eligible set을 고정한 뒤 모든
portfolio form의 최종 대표 metric은 정수 member cardinality 하나다.

| Capability/form | 선행 eligible set | tie metric |
| --- | --- | --- |
| `pc.minimals/min-cover` | exact PC coverage universe | 최소 member 수 |
| `pc.score-minimals/max-score-cover` | pattern별 score-only 최고 candidate rows | 최소 member 수 |
| `build.cover`, `build.congruent-cover`, `build.setup-cover`, `build.evaluate.minimals`의 `min-cover` | exact reachable coverage universe | 최소 member 수 |
| 같은 Build capability의 `max-probability-minimum` | exact union probability의 전역 최댓값 | 최소 member 수 |
| `build.setup-cover-score`, `build.evaluate.score`의 `max-score-cover` | pattern별 score-only 최고 candidate rows | 최소 member 수 |
| `spin-structure.cover/min-cover` | profile/line predicate를 통과한 structure coverage universe | 최소 member 수 |

`max-probability-minimum`은 다음 단계식 의미다.

```text
p* = max exact_union_probability(P)
k* = min |P| such that exact_union_probability(P) = p*
ties = every canonical P satisfying probability(P) = p* and |P| = k*
```

`pc.score-minimals`와 모든 `max-score-cover` form은 B안으로 고정한다.

1. 각 `(candidate, pattern)`의 모든 legal replay 중 최대 정수 score를 구한다.
2. 같은 최대 score replay를 attack으로 줄이지 않는다.
3. 각 pattern의 전역 최고 score를 달성한 모든 candidate를 eligible하게 남긴다.
4. candidate row는 그 candidate가 최고 score를 달성하는 pattern 집합이다.
5. 그 row들로 exact minimum-cardinality cover를 구한다.
6. 모든 equal-cardinality optimal portfolio를 보존한다.

Score equality, eligibility, dominance, ranking, portfolio membership,
canonical order, Discord representative selection에 attack을 사용하지 않는다.
표시용 attack이 필요하면 normalized trace key가 가장 작은 equal-score trace를
대표로 선택하고 `informational_attack_basis=canonical_equal_score_trace`를
명시한다. Score는 exact integer로 비교하며 epsilon이나 `f64` ranking을
사용하지 않는다.

### 2.2 Identity, enumeration, snapshot

공통 계약은 `portfolio-alternative-set.v1`,
`portfolio-alternative-page.v1`, `portfolio-member-page.v1`,
`portfolio-snapshot.v1`로 나눈다.

- candidate ID는 stable normalized solution key를 정렬한 뒤 1부터 부여한다.
- portfolio identity는 오름차순 numeric candidate-ID vector다.
- portfolio 순서는 그 vector의 숫자식 lexicographic order다.
- 기본 단일 결과와 Discord 결과는 첫 portfolio다.
- worker 수, backend, 탐색 순서, hash bucket, 입력 row 순서는 결과를 바꾸지
  못한다.
- set에는 query/source/profile/universe/build identity, candidate-map digest,
  검증된 최적 cardinality, `known_alternative_count_decimal`, nullable
  `total_alternative_count_decimal`, `enumeration_complete`, incomplete reason과
  restart 정보가 포함된다.
- 외부 page는 portfolio 하나를 담고, member page는 result-bound candidate
  dictionary를 100개씩 참조한다.

Enumeration은 semantic top-K 제한 없이 lazy하고 exact해야 한다.

1. 첫 pass에서 정확한 최적값 `k*`와 lexicographically smallest canonical
   portfolio 하나를 증명한다.
2. 두 번째 restartable exact pass가 원본 row identity에서 모든 `|P|=k*`
   portfolio를 열거한다.
3. 최적값 탐색용 dominated/equal-row 축약은 허용하지만 두 번째 pass는 제거된
   equal candidate identities를 복원한다.
4. equal-depth branch를 자르는 기존 single-winner pruning을 all-optima
   enumerator에 사용하지 않는다.
5. 모든 결과를 선물질화하지 않는다. `known_count`는 단조 증가하고 exact
   `total`은 traversal seal 뒤에만 채운다.
6. timeout, cancellation, resource exhaustion, snapshot failure는
   `enumeration_complete=false`와 exact restart 정보를 반환한다. 일부 결과를
   전체라고 표시하지 않는다.
7. generic minimum-cover의 greedy fallback은 product exact authority가 아니다.

### 2.3 정상 family/list는 tie가 아니다

다음 결과는 각 capability의 정상 count/order/paging 계약을 사용하고 tie

- `pc.score`, `pc.best-save`, `pc.score-finder`, `pc.allspin-sol`
- Setup 네 ranked family
- `forward.damage`, `forward.spin`, `forward.ren`
- `spin-structure.search`, `spin-structure.guaranteed`

### 2.4 GUI, CLI, Discord

Main Web workspace, `/pc-solver`, Tauri/Desktop는 result와 함께 portfolio store를
자동 준비한다. 외부 한 page에는 portfolio 하나, 내부 member page에는 100개를
표시한다. 사용자 navigation과 한 page 안전 prefetch에서만 enumerator를
진행한다. JS에 전체 alternative를 누적하거나 client-side 정렬하지 않는다.
현재/이전/다음 page 상태만 유지하며 새 검색, 취소, navigation, dispose, app
exit에서 handle을 해제한다. v0.8에서는 share URL이나 restart 복구를 제공하지
않는다.

CLI 기본 byte/schema 의미는 유지한다. 명시적 경로는 다음과 같다.

```text
clearra <original-command> ... --ties --tie-snapshot PATH
clearra continue --tie-snapshot PATH --tie-cursor TOKEN
```

Snapshot은 versioned append/checkpoint 형식이며 query/build/profile/candidate-map과
exclusive lock에 결합한다. Initial path는 새 파일이어야 하며 existing file,
symlink/reparse target, unsafe parent, concurrent writer를 거부한다. Stale,
tampered, 다른 query/build cursor와 I/O 오류는 typed failure다. 기존 positional
PC continuation token은 그대로 지원하고 parser에서 tie continuation과
fieldwise 구분한다.

Discord에는 tie option, count, explanation, cursor, paging, button, modal,
autocomplete, attachment를 추가하지 않는다. Direct와 remote job 모두 tie
flag를 전달하지 않고 canonical first portfolio 하나만 기존 형식으로
게시한다. Discord validator는 alternative array와 tie metadata를 거부한다.

## 3. Native CTK3/Fumen solution output

`artifact.solution-set`을 v2로 확장한다.

- 모든 solution-bearing native CLI command에서
  `--format text|json|ctk3|fumen`을 지원한다.
- `--solution-artifact-format compact|json|ctk3|fumen`을 지원한다.
- 기본 text/compact 동작은 바꾸지 않는다.
- Portfolio cursor가 있으면 현재 portfolio 전체를 출력한다. 화면의 member
  page 100개만 인코딩하지 않는다.
- 정상 family는 capability의 현재 family/page 계약을 따른다.
- 대규모 CTK3는 기존 segment/bundle 규격으로 streaming한다.
- Fumen은 호환 가능한 multi-page document만 생성하고 표현 불가능한 CTK3
  정보를 silent loss 없이 capability error로 거부한다.
- cancellation, codec, publication 실패를 부분 성공으로 보고하지 않는다.
- Native file output은 atomic-new-file, no-overwrite, symlink rejection을
  유지한다.

Native CLI는 Node/TypeScript subprocess나 network codec을 사용하지 않는다.
언어 중립 `docs/ctk3.md`와 shared conformance fixture가 wire authority다.
`packages/ctk3`는 browser/Discord TypeScript 구현을 유지하고 새 native Rust
codec은 같은 fixture의 canonical bytes, document identity, checksum,
page/color/comment/operation, segment/bundle 동작을 맞춘다. `clearra-output`은
codec을 복제하지 않고 typed writer dispatch만 소유한다.

## 4. Capability implementation

### 4.1 PC

- `pc.path`: legal replay/path evidence를 materialize하고 candidate, pattern,
  trace, hold transition, consumption, line-clear identity를 보존한다.
- `pc.minimals`: 기존 exact single canonical cover를 보존하면서 공통 all-optimal
  enumerator/store를 연결한다.
- `pc.score`: score-only selection/order로 좁게 수정하고 equal-score/different-
  attack candidates를 정상 family로 보존한다.
- `pc.score-minimals`: B안 `pc-score-portfolio.v2`를 완성하고 candidate,
  coverage, legal replay evidence를 분리 보존한다.
- `pc.saves`: terminal hold + active-bag remainder canonical multiset을 public
  save-group identity로 사용한다. 동일 `(group, pattern)`의 여러 trace는 pattern
  weight를 한 번만 더한다. 전체 universe probability와 conditional-given-PC를
  분리하고 bag provenance가 없는 fixed source는 fail closed한다.
- `pc.best-save`: `clearra-save-v1`의 lexicographic tuple
  `(T6/I4/O3/J1/L1/S0/Z0 weighted total, min(J,L), exact group probability)`을
  사용하며 모든 exact 동점 winner를 정상 목록으로 반환한다.
- `pc.score-finder`: fixed queue의 최고 정수 score witness를 모두 반환하며
  attack을 선택/정렬에 사용하지 않는다.
- `pc.allspin-sol`은 full preserving solution family 보존 characterization을
  유지하고 Discord에서만 canonical first witness를 고른다.

### 4.2 Build options와 capabilities

- `build.queue-knowledge`: `oracle|visible-7`, 기본 `oracle`. `visible-7`은
  `(current hold, visible next 7)` observation class 내에서 동일 action을 요구하는
  exact policy다. `tiling-only`와는 불가하다.
- `build.objective`: `all|unique|min-cover|max-probability-minimum|max-score-cover`.
  호환 alias는 `minimum-cover -> min-cover`만 유지한다. Fixed subcommand와 같은
  objective는 허용하고 충돌은 실행 전에 거부한다.
- `build.score-profile`: `tetrio|guideline|jstris-ultra`, 기본 `tetrio`.
  Score-capable form에서만 허용하고 모든 builtin은 현재
  `basic-approximation`, `profile_specific_exact=false`를 공개한다.
- `build.initial-b2b`: `0..65535`, 기본 0. Score-capable form에서만 허용하며
  coverage/probability union을 바꾸지 않는다.

12 Build capability는 공통 geometry, realization, BuildOrder, HoldAutomaton,
coverage evidence를 재사용한다. Probability는 candidate 확률 합이 아니라
PatternBitSet OR union으로 계산한다. Supplied-solution evaluate는 input identity와
replay legality를 검증한 뒤 같은 reducer를 사용한다. Partial universe, replay,
weight를 authoritative probability, score, winner로 승격하지 않는다.

### 4.3 Setup, Forward, Spin structure

- Setup primary rankings은 각각 exact Joint, Build, conditional PC,
  score-only다. 모든 동점 setup은 정상 family다. `setup-length`는 별도
  deterministic rule이며 `auto`는 all/build에서 longer, pc에서 shorter다.
- `forward.damage` maximum은 최고 damage의 모든 outcome/path를, at-least는
  predicate를 통과한 모든 결과를 반환한다.
- `forward.spin`은 ordered queue/hold search이며 public identity는 terminal spin
  outcome이다. Movement/kick trace 차이는 evidence로 접는다.
- `forward.ren`은 exact fixed queue, 최대 22 pieces, initial hold empty, hold on
  기본이다. 시작 board의 완성 행은 지우되 REN에 세지 않는다. 각 accepted
  lock은 줄을 지워야 하며 `ren_count=max(line_clear_count-1,0)`이다. 첫 piece가
  clear하지 못하면 no-solution이다. Maximum REN의 모든 distinct witness와
  multi-parent trace DAG를 보존한다.
- Spin structure는 unordered inventory/no-hold authority를 forward spin과 분리한다.
  Search와 guaranteed는 정상 structure family이고 cover만 exact portfolio tie다.

### 4.4 Utility, profiles, artifact

- `utility.parity`: global coordinate 기반 static observation만 반환하고
  `feasibility_claim=false`, `pruning_authority=none`으로 고정한다.
- `utility.to-gray`: occupancy color만 gray로 바꾸고 page/operation/comment/
  garbage/dimension identity를 보존한다.
- `utility.render`: bounded deterministic typed-document render만 수행한다.
- `utility.fumen`: combine/split/mirror/comment/operation transform을 typed
  document에서 수행하고 표현 불가능한 정보는 거부한다.
- `utility.sequence`: provided operation traces를 lossless normalize/replay-
  validate한다. Exact order 탐색은 하지 않는다.
- `utility.sequence-dependencies`: actual reachability 기반 exact
  `OperationOrderLanguage`를 구현한다. Queue/hold 없이 initial board, concrete
  operation multiset, rule/kick profile만 사용한다. Dynamic word span으로 최대
  4,096 operations, `dependency_long=900 seconds`, arbitrary-precision decimal
  count, universal precedence closure와 deterministic transitive reduction을
  지원한다. Incomplete graph에서 absolute dependency를 게시하지 않는다.
- `utility.mirror`: field/page/operation/rotation typed transform과 double-mirror
  identity를 검증한다.
- `request.profiles`: board/piece/bag/rule/spin/score profile을 request-local로
  선택하고 unsupported/unverified profile은 fallback 없이 거부한다.
- `artifact.solution-set`: native CTK3/Fumen v2와 current portfolio/family
  export를 연결한다.

## 5. Runtime/release requirements

### 5.1 `REQ-V080-013` durable delegation journal

Two-phase publication 순서는 `Prepared` durable ACK → non-executable offer →
worker accept ACK → `Accepted` durable ACK → `Published` durable ACK → executable
payload다. 상태는 `Prepared → Offered → Accepted → Published → Running/Renewed
→ ResultSealed → ResultApplied → Completed`이며 terminal은
`Revoked|Expired|Cancelled|FailedClosed`다.

기본 시간은 offer acceptance 10초, heartbeat 5초, persisted renewal 최대 30초,
active lease expiry 120초, terminal/dedupe tombstone 24시간이다. Corrupt,
unresolved, unknown-commit journal은 TTL 삭제하지 않고 quarantine한다.
Native journal은 per-job canonical UTF-8 JSON Lines, decimal u64, monotonic
sequence, prior/event SHA-256 chain, append+flush+`sync_all` 후 ACK를 사용한다.
Browser는 IndexedDB, tests는 injected clock/ACK failure journal을 사용한다.

## 10. 승인된 구현 계약

2026-08-27 read-only gap audit에서 분리한 아래 Utility, durable delegation,
`pc.minimals` WASM stack 계약은 같은 날 사용자가 전부 승인했다. 따라서 이 절은
앞 절과 동일한 규범 목표이며 별도 승인 없이 구현·검증·배포한다. 구현 중 이
계약으로도 의미가 하나로 정해지지 않는 새로운 문제가 생긴 경우에만 작업을
일시정지하고 질문한다.

### 10.1 Typed-document Utility 계약

1. Host/JSON typed envelope에는 `format=ctk3|fumen`을 필수로 둔다. Native CLI는
   `--document TEXT`와 `--document-file PATH` 중 정확히 하나를 받고, canonical
   prefix가 유일할 때만 format을 추론한다. Ambiguous input, plain grid, link file,
   16 MiB 초과, 4,096 page 초과는 거부한다. 결정적 transform에는 timeout/search/
   queue/hold/backend/worker option을 노출하지 않는다.
2. `utility.parity`는 result-bound page source로 page 하나씩 운반하고 public page
   번호는 1부터 시작한다. CLI/GUI가 전체 page를 탐색하며 Discord는 첫 page만
   bounded summary로 표시한다. 모든 page의 `feasibility_claim=false`,
   `pruning_authority=none`과 별도 `pending_garbage_occupied_cell_count`를 유지한다.
3. `utility.fumen`의 closed transform은 현재 actual codec이 증명한 `roundtrip`,
   `combine`, `split`, `get-page`, `page-shift`, `clean-comments`,
   `preserve-comments`, `to-gray`, `mirror`, `text-to-fumen`으로 한정한다. 별도
   generic operation-edit는 v0.8에 만들지 않는다. Combine은 repeated document/
   JSON array, split은 `field-document-set.v1`, get-page는 1-based, positive
   page-shift는 signed left rotation, text-to-fumen은 bounded Unicode comment
   array로 정규화한다.
4. Transform의 native text 출력은 canonical encoded document, JSON은 typed
   payload, 파일 출력은 atomic-new/no-overwrite로 한다. Web/Desktop은 copy와
   download를 모두 제공하고, Discord는 짧은 summary와 canonical attachment만
   게시한다. 원본 filename을 권위로 보존하지 않고 format 기반 안전 이름을 쓴다.
5. `utility.render`는 같은 Rust exact bitmap renderer를 WASM에도 포함한다.
   PNG는 선택한 1-based page 하나, GIF는 document page order의 timeline이며
   operation replay를 별도 frame으로 합성하지 않는다. Pending garbage는 typed
   garbage row로 그린다. Product default export limit과 Discord attachment limit을
   동시에 만족하지 못하면 typed failure다.
6. 실제 cat skin/animation authority가 없는 `sfinder-man/catimage` preset은
   임의 asset을 만들지 않고 v0.8 exclusion으로 재분류한다. 사용자가 cat skin을
   명시적으로 요구하면 별도 asset provenance와 render KAT를 먼저 확정한다.
7. `utility.render`는 target public surface가 없더라도 exact Rust renderer library
   foundation이 있으므로 `partial`은 유지하되, 현재 잘못된
   `legacy-render-file-command` evidence를 제거하고 비공개 library 근거로
   `current_surface`를 정정한다.

### 10.2 Durable delegation 계약

1. Native durable 단위는 verifier `Initialize`, 각 `Consume`, `Finish` 각각이다.
   Candidate batch만 journal하고 lifecycle의 앞뒤를 비권위로 남기지 않는다.
2. `Running`은 worker가 executable payload와 permit을 검증하고 start ACK를 보낸
   뒤의 상태다. `ResultApplied`는 actual merger가 성공한 뒤, `Completed`는 그
   durable ACK 뒤에만 기록한다.
3. v0.8 durable mode는 streaming partial 적용을 하지 않고 immutable final result를
   seal한 뒤 exactly-once application한다. Retry execution보다 at-most-once task와
   새 identity의 explicit retry를 사용한다.
4. Process restart에서 `Prepared`, `Offered`, `Accepted`, `Published`, `Running`,
   `Renewed`, `ResultSealed`, `ResultApplied` 등 모든 unresolved non-terminal phase는
   자동 resume하거나 TTL 삭제하지 않고 quarantine한다. Result bytes와 application
   transaction을 별도로 durable하게 만들기 전에는 복구 완료를 주장하지 않는다.
5. `ResultSealed` digest는 merger-ready canonical normalized final result 전체를
   결합하고 worker reply digest를 별도 transport evidence로 보존한다. 같은
   task/fence/result digest의 duplicate는 한 번만 적용하고 다른 digest는
   fail-closed한다.
6. `job_id`는 journal header에 durable하게 저장한 UUID, `task_id`는 job과 operation
   ordinal의 결정적 identity, `coordinator_id`는 source commit과 boot UUID,
   `worker_id`는 job-local numeric index로 한다. `request_sha256`은 raw command text가
   아니라 canonical typed query와 compiled problem/profile/catalog identity를 묶는다.
7. `WasmBuildProbabilityCandidateProducer`가 만든 actual canonical packet stream 하나를
   native/browser KAT 양쪽이 공유한다. Arbitrary test payload나 서로 다른 producer를
   “one candidate source” 증거로 인정하지 않는다.
8. Terminal tombstone reset은 24시간 경계 뒤 startup/explicit maintenance에서만
   compare-and-reset한다. Quarantine은 read-only inspect/archive만 허용하고 같은
   identity의 unquarantine/resume은 제공하지 않는다.
9. Native public route는 명시한 thread stack size, channel capacity/control block,
   batch/result owners를 provider-backed actual bytes로 admission한 뒤에만 연다.
   처음부터 요청된 bounded worker 수 전체를 계상하며, accounting이 없으면 serial
   성공으로 낮추거나 `REQ-V080-015`를 우회하지 않고 unavailable을 유지한다.

### 10.3 `pc.minimals` WASM stack 계약

Actual `WasmCommandRuntime::run_command_text(pc.minimals)` producer E2E는 native
debug libtest의 기본 2 MiB stack에서 overflow하고 명시적 4 MiB stack부터 통과했다.
`WasmAbiState` inline 크기는 37,456 bytes이며 governed owner 이관 재귀는 원인이
아니었다. 이 현상을 test-only stack 증설로 숨기지 않고 product runtime defect로
취급한다. 큰 parser/producer stack frame과 temporary를 fieldwise 측정해 governed
heap owner 또는 bounded store로 옮기고, 2 MiB native regression과 실제 wasm32
release worker E2E를 둘 다 통과한 뒤에만 page-owner lifecycle과 Web source
fingerprint를 acceptance한다. WASM stack 자체 증설은 high-water·artifact memory
budget·browser별 실행 증거가 별도로 생기기 전에는 사용하지 않는다.

10.1/10.2/10.3은 앞 절의 test matrix와 release gate에 합쳐 검증한다. 이 절 중
일부만 구현된 상태를 전체 public capability 또는 release 완료의 증거로 사용하지
않는다.
