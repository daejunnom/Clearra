as a work/review convention only. In-flight implementation, focused validation,

## First candidate handoff

Use the empty 10×4 Jstris 180, 4L P7P4, 10 locks/11 supplied pieces, CountUnique,
enabled-empty hold, full-future universe, automatic all-logical workers, with
legacy data accelerators off. Reference and candidate must complete without
truncation and agree for every one of 456,459 canonical identities on its exact
original queue set and integer-weight probability. Both global unions must be
4,233,600 of 4,233,600. Stream bounded ranges or an exactly comparable
representation; an aggregate, hash, sampled mapping or dense full matrix is not
the verifier. Test detection of a swapped mapping with unchanged global union.

Adopt a new accelerator only on repeatable time improvement with non-regressing
supervisor peak: matched ABBA and BAAB, one axis per comparison, both block
medians faster, pooled improvement beyond baseline MAD and resolution; peak
median and maximum within baseline measurement variation. Record all outcomes
including censored runs. Use the manager for finite large runs. Do not reuse
unfinished historical executions as samples.

## Follow-on integration work (not qualification)

- A separate, default-off later-ordered-kick experiment accepts a Boolean
  edge only when prior kick candidates are provably blocked and the real
  landing remains valid. It measures attempts, proofs, and consumed proofs
  separately. The comparison checks all 42 original queue ordinals of the
  seeded 10×3 case against the independent traversal. CountAll, replay, and
  scoring do not consume this Boolean certificate.
- A further default-off axis, `CLEARRA_ORDERED_KICK_GUARD_REUSE=1`, reuses
  the witness only within the current candidate's Boolean graph. Keep the
  same first/later-kick flags on both arms. The guard retains an occupied
  blocker for each earlier viable kick (and support if not on the floor),
  and reserves empty cells for the original route and selected lock. It is
  bound to one physical pose and deletion frame. A miss runs the existing
  exact path; a contradiction discards the uncommitted graph and retries
  once without candidate certificates. Count actual selected reuses
  separately from constructed guards. This is not a primitive-trace or
  performance qualification, and the existing P7P4 handoff pins it off.
- Compact ILC shares the target-row availability summary across projections.
  Its separate, default-off lazy-frame memo borrows immutable,
  request-owned instances, with exact-order fallback on a slot collision.
  Do not combine it with the ordered-kick or movement-clear A/B.
- Full-height fixed-queue scenario replay preserves upper occupancy words
  in a versioned token without changing the existing compact format. A
  high-occupancy query with additional unsupported constraints does not
  receive a lossy public replay token. Separate CLI/Desktop and Web WASM
  worker tests cover both successful and impossible full-height supply.
- The 10×4 Legacy Cover probe joins a normalized concrete candidate to its
  verified native coverage row by ID. It is an explicit qualification probe,
  not a routine unit test or proof of complete positive Legacy Cover parity.
  Source tracing additionally found that the native 4×1 rejection follows
  from a complete observed source compiling an empty packing multiset,
  not a general width restriction. The 10×4 source has a truncation
  exemption for that multiset. Two distinct physical layouts can complete
  its same ordinal 0, even when the template contains one concrete assignment.
  The native reducer's positional row-count check cannot establish that
  assignment's result. Keep the positive Rust product route closed until
  the concrete assignment-to-candidate join has its own parity evidence.
  The test-only Rust candidate provider exercises an exact positive 4×1 I
  request end to end through the original ordinal and identity-keyed reducer.
  This is not C parity: the native fixture is still outside C admission.
  For 10×4, C can finish coverage of the requested materialized prefix even
  when the source is truncated, but public Cover still reports that result
  as incomplete. A prefix witness must not bypass that distinction.
- [Operation and ABI ownership](research/v090-ownership-and-abi-contract.md)
  separates known Rust users of the production C archive, independent
  reference oracles, and public/external compatibility still to verify.
- The horizontal-component no-entry experiment uses actual bidirectional
  translation edges to compress the bounded reverse closure. It checks all
  optimistic predecessor edges and the actual sky seeds; an opening or
  exceeded work budget is Unknown. Its flag is `CLEARRA_NO_ENTRY_COMPONENTS=1`
  and requires movement-clear in both arms when compared.
- The SameTile reuse experiment avoids a group scan only when one member's
  exact common-owner mask proves all of that member's parents already cover
  the entire group. `CLEARRA_SAME_TILE_PARENT_REUSE=1` applies to advanced
  non-empty Geometry, not the empty P7P4 case. Track avoided scans as well
  as identity parity.
  The supervised benchmark's `--nonempty-eight-i` mode checks the seven
  identities of a 4×8 rectangle and its single fixed queue against an
  independent enumeration. It refuses an inactive selected route, and
  `--compare` checks the observed topology as well as result parity.
  Focused Linux CI exercises each of reference, incremental, and SameTile
  modes; those smoke runs do not qualify throughput.
- `CLEARRA_MINIMUM_DOMAIN_CUTOFF=1` is a separate experiment for the minimum
  route, including eligible empty-origin searches. A cell stops scanning
  only when its viable-parent count reaches the incumbent, so it cannot beat
  the earlier pivot. All remaining cells must still be checked for zero
  support. Winner support masks, bumpers, and resource admission are unchanged.
  Use `CLEARRA_MINIMUM_DOMAIN_WORK=1` on both arms for work reduction, and a
  separate run with work counting off for wall time. The existing P7P4
  movement-clear handoff forces both flags off; it cannot qualify this axis.
- Setup Score groups candidates by normalized continuation board and only
  shares validated Rust scoring on full query equality. Candidate-specific
  Build coverage is never shared. The authorized Web verifier similarly
  releases its received JS batch slot on handoff to synchronous WASM start,
  without altering the wire bytes or authorization checks.
- The Boolean standard-bag evaluator stops walking the same successor twice
  when Current and SwapHeld consume and retain the same piece. The ordered
  action multiplicity in CountAll is a separate contract. The occupied-hold
  regression checks the precise per-identity success set of 12 out of 42
  original queues, alongside an independent count of 18 action histories.
- The integration workflow separates the actual native CLI/Desktop readback
  from the C Legacy Cover checks. Its 7–24L fixtures exercise the bridge, not
  the deployed Desktop window or browser; it does not install any new
  accelerator generation.
- CEGIS now shares original-row contributor groups and the explicit
  floor/initial/alternative-support predicate. An unexecuted placement
  remains only a possible supporter; a geometric frame or support fact is
  not a reachability proof. Independent scalar-grid tests cover simultaneous
  row removal and support alternatives using stable concrete placement bits.
  A bounded follow-on admission also checks atomic row groups cleared by
  one concrete operation. The new 4L SRS90 witness loses I's existing
  support when J clears original row 2; T or O can restore it in that new
  frame. The actual proof must still certify all six valid orders and their
  six original queue ordinals, without treating geometric admission as
  physical reachability. This remains under the conditional-order experiment.
- Terminal result assembly transfers per-solution coverage ownership out of
  the search session and frees the now-unused lookup before assembling keys
  and typed evidence. It does not claim an RSS reduction for P7P4 global-only.
- The exact Legacy Cover reducer can join a complete, scoped row to its
  concrete assignment without using C candidate positions. Explicit empty
  rows are distinct from missing proof; equal colored masks do not identify
  distinct placement splits. The existing native route does not use this
  reducer yet.
- The native/Rust 2L tiling control gate explicitly distinguishes typed
  cancellation, a deterministic candidate-budget cut, and a complete empty
  family. The App adapter shares one direct/cooperative response path and
  preserves an explicitly matched compute-budget failure without exposing a
  partial family. Positive memory and page-store evidence are still
  required to publish a complete family.

## Experimental follow-on and reproducible proof

The second CEGIS counterexample is the SRS90 I/O/T placement on 10×3
`0x3f0f83f4` (I `0xf00000`, O `0xc03`, T `0x7008`).
Its exact no-hold order language is `{OIT, OTI, TIO, TOI}`; every pair
can occur in either order, so a conjunctive precedence graph cannot
represent this case. The independent first-kick experiment checks the real
sky seed, straight-down predecessor path, and raw first kick. Conditional
order compilation has its own small state/check budget; an unknown edge
prevents publishing a language. Both are still off by default.

The per-solution proof path exports symbolic P7P4 roots as runs of exact
840-bit tails. The receiving sorter merges overlaps per solution and the
reader checks both completed streams. It never infers coverage from a
worker-local root ID. Single-run disk limits are 16 GiB spill plus 8 GiB
final, and the two-arm driver requires 33 GiB free. Capacity estimates and
small proofs are not large-case evidence.

On a clean exact-source checkout, build the native release manager and
`placement_graph_bench` example with `parallel,local-search-ab`. Set
`CLEARRA_SOURCE_COMMIT` to the full checked-out SHA **when building the
example**, then run:

```text
node scripts/benchmark/run-placement-coverage-proof.mjs --case p7p4 --id p7p4-proof --source-sha FULL_SHA
```

The same proof is isolated in the qualification workflow's dedicated
`codex/v090-relation-rust-p7p4` trigger. Run the dedicated trigger only
after focused tests on its exact SHA; it has no production credentials.
The local timing recorder reuses a completed mapping from the same binary,
supervisor and host. It verifies both captured artifact identities and then
runs global-only ABBA + BAAB sequentially. It stops on a censored or
confounded outcome; an older comparison without compile-time source
provenance does not authorize timing adoption. This command neither compares
raw queue files again nor issues a release receipt:

```text
node scripts/benchmark/run-placement-graph-adoption.mjs --id p7p4-timing --proof-id p7p4-proof --source-sha FULL_SHA
```

For a hosted Linux comparison, the storage and runner identity are shared
only when qualification and timing execute in the same job. Before the
workflow is on the default branch, the owner can opt in by creating exactly
`codex/v090-relation-rust-adoption-<full-source-SHA>` at that SHA after its
focused checks pass. Normal integration pushes launch no timing; this
dedicated job retains bounded JSON only and never activates an experiment.
For separate host readback, the owner can opt in with
`codex/v090-relation-rust-host-<full-source-SHA>` at exactly that SHA.
It builds product WASM once without accelerator downloads and exercises
the production verifier in Node Worker realms, then the same verified WASM
in actual Chromium at the supervised loopback port 4194. The browser
cases use 1L fixed-I PC, 24L forced PC, and 4L mirrored-I Build and require
real peer work plus serial/distributed equivalence. The other job reuses
the same native CLI build for the Desktop bridge and Discord adapter checks.
These are deliberate non-publishing checks, not full Svelte/Pages UI,
Tauri-window readback, Cloud Run deployment, or C retirement.

The next focused increment separates four kinds of evidence:

- Conditional order reuses the physical projection while the deleted-row
  frame is unchanged. A new clear reconstructs the post-lock board from
  original surviving cells. The 4L OR fixture compares every subset and
  next-operation projection with the independent reference, then still
  checks the physical transition and original-queue coverage.
- The test-only native/Rust 10×4 cover comparison admits an exact prefix of
  a truncated original source without upgrading it to a complete source.
  A matching bit for the original ordinal 0 certifies only that witness,
  not completeness or a product probability.
- Component shuffles with shared hold are checked against finite concrete
  action enumeration. Boolean success is a union on original queue ordinals;
  concrete action multiplicity and original weights are separate. Independent
  component marginals or a sum of overlapping serial words are not exact.
- Native parallel experiment receipts separate worker-exit scratch and
  outbound payload from coordinator handoff and terminal assembly. These are
  selected logical capacities, potentially at different points in time, and
  are not additive across checkpoints. Use supervisor RSS for measured process
  memory; neither metric alone is an adoption decision.
