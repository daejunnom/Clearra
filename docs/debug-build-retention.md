# Temporary debug build retention

Temporary native debug artifacts retain **one generation per logical target**.
Cargo's shared dependency graph is not one self-contained executable: deleting
all but one file from `debug/deps` would corrupt other retained targets.

- `debug/incremental/<unit>-<variant>`: keep the most recently updated variant
  for each compile unit. Incremental caches are disposable, not release evidence.
- `debug/deps/<target>-<hash>.exe`: keep the newest non-empty executable for each
  target, together with its matching `.pdb`, `.d` and `.exp` files. A PDB alone
  is not treated as an executable generation. This is a retention rule, not a
  correctness or completed-release attestation.
- Shared `.rlib`, `.rmeta`, build-script dependencies and Cargo fingerprints are
  retained. Release profiles and published GUI/WASM artifacts are never pruned
  by this policy. Published WASM retains its separate five-generation policy.
- On Windows, skip while Cargo, rustc, link, a debug executable, or Cargo's
  profile lock is in use. Reject reparse points and any deletion outside the
  explicitly selected `debug` directory. No build/test runs during cleanup.

The normal PowerShell progress runner applies the policy after a debug Cargo
command and its requested test/run process have exited. Cleanup does not change
the command's exit code. Release commands are excluded.

Ad-hoc diagnostics should use `scripts/tools/invoke-clearra-debug-cargo.ps1`
with the explicit shared Cargo target directory and Cargo arguments. This also
sets `CARGO_INCREMENTAL=0` for that process, matching the official runner.
Unwrapped `cargo` commands cannot run the repository's post-process hook; do
not use them for repeated temporary debug variants.

For an existing cache, inspect the plan before applying it:

```powershell
& ./scripts/tools/retain-clearra-debug-builds.ps1 -CargoTargetDirectory '<absolute-cargo-target>'
& ./scripts/tools/retain-clearra-debug-builds.ps1 -CargoTargetDirectory '<absolute-cargo-target>' -Apply
```

Cleanup deletes generated files permanently, not to the Recycle Bin; they can
be regenerated by compiling the relevant target. It does not delete source,
credentials, user inputs, release files, or the currently published 4194 WASM.
