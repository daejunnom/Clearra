# Full 6L P1P7P7 전체 열거와 정확한 원본 큐 확률

## 완료 기준과 현재 상태

**현재 Full 6L 완주는 확인되지 않았다.** 아래 시간 제한 실행은 병목을 조사한
미완료 진단이다. P7P4의 456,923개 해답은 `e6301cdb`에서 재확인했다. 후속 수정의
완료 실행과 회귀 결과는 검증 후 갱신한다. 파일명은 작업 식별자이며 사용자
정정·검증일은 한국 시간 2026-11-23이다.

완료 기준은 **전체 후보 영역 소진, 정확한 정규화 해답 집계, 원본 큐 확률 계산**이다.
Coverage 100%의 조기 증명으로 전체 열거를 대신하지 않는다. 초기 작업에서 전역
확률의 빠른 양성 증명을 목표로 해석하고 분기 순서와 조기 종료를 추가한 것은
이 요구에 맞지 않았다. `2d69d7d3`에서 해당 API, typed global evidence, 전용 App
하네스, geometry streaming과 coverage 조기 종료를 제거했다. 역사 자료는 Git 이력과
원본 산출물에 보존한다. 초기 coverage 증가를 전체 열거 속도 개선으로 인용하지 않는다.

이 작업은 [P7P7 완료 기록](oracle-p7p7-full-draw-2026-11-22.md)을 계승한다.
사용자는 GitHub feature branch 게시를 허가했다. 11미노 see-7은 범위에서 제외한다.

## 1. 입력 계약

| 항목 | 정확한 계약 |
| --- | --- |
| 보드와 목표 | 빈 10×6, ClearToEmpty |
| 실제 lock 수 | 정확히 15 |
| 공급 | 유한한 factorized expression `P1P7P7` |
| 원본 큐 | `7 × 5,040 × 5,040 = 177,811,200`개 |
| atom 선택 순서 | `IOTSZJL` |
| ordinal | `first_rank × 5,040² + bag1_rank × 5,040 + bag2_rank` |
| 관측 | FullQueueOracle, 실제 15 draw 전체 공개 |
| 규칙과 Hold | SRS+, 초기 빈 Hold, 사용 허용, 실제 EOF의 held-release 보존 |
| projection | unplaced lookahead는 true, 보이지 않는 standard-bag complement는 false |
| 결과 | Unique, CountUnique, output `trace`, chance evidence `Disabled` |
| 병렬 | Auto, 전체 논리 프로세서. 이 환경에서 9 workers |
| accelerator | cold, tablebase·legal-board·conditioned-reachability 비활성 |
| 생성 한도 | nodes/frontier/candidates/patterns 모두 0, 명시 memory budget 없음 |

첫 한 미노는 독립 선택이고 뒤의 두 atom은 새로운 7-bag다. 같은 cardinality의
Standard7Bag 15 draw로 치환하거나 16번째 미노를 가정하지 않는다. `max_results=256`은
출력 예산이며 후보 생성 상한이 아니다. 외부 감독의 메모리·진단 시간 경계에 도달한
실행을 제품 탐색의 성공으로 보고하지 않는다.

## 2. 정확한 공급과 성공 판정

실제 complete uniform factorized backing의 atom, choice order, draw count, suffix
count를 확인한 capability를 사용한다. 기하 multiset은 `[2; 7] + e_k`인 일곱 개다.
원본 ID 레코드 177,811,200개를 만들지 않고 일곱 key와 source extent를 공유한다.

공유 extent는 target membership의 상위 집합이며 성공 coverage가 아니다. 성공은
정확한 물리 실행 언어와 **실제 source/Hold/EOF 언어의 교집합**에서 얻는다. Partial
atom의 남은 choice를 다음 atom으로 넘기지 않고 실제 draw 경계에서 버리는 의미,
원본 ordinal과 최소 witness를 보존한다. Memo와 공유 request는 전체 schedule과
Hold/EOF 설정을 비교하며 hash만으로 다른 source를 합치지 않는다.

정적 의존성 그래프의 비순환성과 원본 큐 존재를 동치로 가정하지 않는다. 동치가
성립하는 조건, OR realization과 AND row contributor의 구분, 구체적인 반례는
[정확성 검토](dependency-cycle-queue-exactness-2026-11-23.md)에 정리했다.

## 3. 전체 family 생성의 실제 작업 감소

- Minimum-domain cutoff는 현재 최선의 support 수 이상이 확인된 cell의 나머지
  incidence 검사만 생략한다. Pivot·동률·kind mask·zero-support 판정은 보존한다.
- 같은 frame에서 불허 support row를 연속 처리하고 첫 허용 row에서 멈춘다.
  Residual 진입, child, memo 조회와 family commit 순서를 보존한다.
- 한도가 없는 경로의 family chunk directory를 amortized 방식으로 늘린다.
  한도가 있으면 기존 최소 성장 방식을 유지하여 여유 capacity 때문에 기존 탐색이
  새로 거절되지 않게 한다.
- 실제 chunk capacity 합을 누적하여 retained bytes 조회를 O(1)로 만든다.
  Rewind에서는 제거된 capacity만 차감하고 부분 truncate의 capacity는 유지한다.

이 네 변경은 기존 memo/DAG와 전체 후보 열거를 유지한다. 아래 후속 최적화와는
분리하여 검증했다. ILC logical placement와 기존 SRS+ 이동 판정은 동일하다.

`fb9ab33a`에서는 실제 일곱 target에서 인증한 `[2; 7] + e_k` inventory의 동일한
잔여 공급 집합을 공유한다. Raw prefix 7,290개를 동일한 잔여 집합 4,246개로 대응시키며,
원본 큐나 Hold 상태를 이 key로 합치지 않는다. 또한 같은 후보·subset·operation·board와
original-row frame 안에서 같은 lock footprint의 collision·grounding·line clear·projection
사실을 재사용한다. Rotation·pose별 SRS+ 이동과 source product는 그대로 검증한다.

후속으로 선택한 operation prefix의 **불가능성만 증명하는** ILC closure를 연결한다.
아직 선택하지 않은 operation이 담당하는 행은 낙관적으로 삭제 가능하다고 놓고,
선택한 각 operation의 모든 realization을 OR로 유지한다. 이 완화에서도 순환 대기가
남는 subtree만 제외한다. 통과는 Unknown이며 물리 성공이나 가능 큐 존재를 뜻하지
않는다. 순수 family compiler의 residual memo에는 이 prefix별 결론을 저장하지 않는다.
정의와 건전성 증명은 [별도 검토](dependency-cycle-queue-exactness-2026-11-23.md)에 있다.
이 연결은 `785baa31`에 포함했고 테스트 fixture 보정을 `0fbec64f`에 기록했다.
실제 Full6L 입력의 활성화, 작은 전체 해답 집합 보존과 yield 회귀를 통과했다.
성능 결과는 별도 릴리스 실행으로 확인한다.

## 4. 완료 권한과 잘못된 양성 수정

제한 source에서는 symbolic root가 살아 있어도 실제 보존된 원본 큐와의 교집합이
비어 있을 수 있었다. `covers_any_pattern`은 실제 `covered_pattern_count != 0`으로
판정한다. `[I,O]`만 보존한 source와 `[O,I]` 언어에 대해 non-REJECT root, 실제 count 0,
witness 없음, bitmap 0, 최종 buildable false를 모두 확인한다. 양성 대조군도 같은
owner에서 실행한다.

Geometry가 소비한 후보의 검증이 취소되면 새 control로 재개해도 해당 후보를 검증한
것으로 취급하지 않는다. 전체 observation-family 권한을 철회하고 count/probability
미완료를 유지한다. Parallel 완료는 모든 branch가 실제 `GeometryAdvance::Complete`에
도달한 경우에만 허용한다.

## 5. 계측과 중간 관찰

준비를 target preparation, family compile, path-count 및 enumerator handoff,
task split으로 나눈다. 내부에는 residual lookup, feasible inventory, cheap
projection, minimum/advanced domain, advanced prune, component plan, family
commit, support rows를 기록한다. 내부 work count는 로컬에 누적한 실제 횟수이고,
타이머·invocation count는 샘플 가중치를 가진 추정치다. 중첩 span 합을 exclusive
wall time이나 정확한 후보 수로 해석하지 않는다.

| `7e8c3b37`, ordinary Unique 180초 | 25.979초 | 153.953초 | worker 진입 전 취소. 초기 local A/B 빌드 |
| `5ca0600e`, ordinary Unique 180초 | 0.087초 | 179.877초 | factorized 공급 적용. worker 진입 전 취소 |

| `e6301cdb`, ordinary Unique 600초 | 0.124초 | **171.620초** | 원시 family count 확정 후 9 workers 검증. 600초 cooperative 취소. 미완료 |

`e6301cdb`에서는 **원시 기하 후보 247,794,216,021,372개**를 계산했다. 이는 물리적으로
불가능한 후보까지 포함한 family path 수이며 해답 수가 아니다. Family compile은

실제 compile expanded states는 22,654,054개, family node는 52,325,237개다.

같은 non-AB feature 집합의 두 600초 진단에서 직렬 준비 wall time은 305.657초에서
171.620초로 약 43.85% 감소했다. 단일 쌍의 계측이고 후자에 세부 계측이 추가되어
있다. 전체 Full6L의 완주 속도 개선율로 해석하지 않는다. 이후에 펼치는 약 248조
개의 후보 영역에도 구조적인 작업 감소가 필요하다.

`e6301cdb` 실행의 kernel RSS high-water는 3,398,213,632 B, supervisor의 별도 sampled
process-group peak는 3,398,909,952 B였다. `5ca0600e`의 대응 수치는 각각
3,446,464,512 B와 3,349,585,920 B다. 메모리 압력·자동 재시도·강제 timeout은
없었다. 준비 이후 가장 큰 sampled stage는 build-order reachability였다. Projection
work의 32,768 배수는 부분집합 universe 크기 계수이며 실제 그만큼의 상태를 계산했다는
뜻이 아니다. Graph는 도달한 subset만 생성한다.

## 6. 집중 검증

- Family work reduction **4/4**: mixed ILC와 fixed 10I/8I의 전체 node graph, root,
  count, 순서 있는 후보·row ID·identity·해시, canonical shard, 취소. Mixed ILC의
  실제 advance 호출은 **129,576 → 13,636**이었다.
- Family 저장 **5/5**: 실제 capacity, exact-cap/one-under, partial rewind/refill과

- Minimum cutoff **4/4**: Full6L catalog의 314개 상태에서 incidence 1,853,256개 중
  631,714개 검사, 1,221,542개 생략. 전체 반환값 동일.
- 제한 source의 잘못된 양성 **1/1**, consumed-candidate 취소 **1/1**,
  sampled timer와 exact work 분리 **1/1**.
- Factorized source **8/8** (`d9225aa1`): 실제 P1P7P7의 live 언어/동일 inventory에서
  원본 큐 교집합이 빈 경우, 원래 108개 큐의 exhaustive finite-Hold 대조와 전체
  P1P3P3 bitmap 대조 포함. 작은 source가 Explicit로 저장되는 parser 계약 때문에
  처음 fixture를 수정했으며 제품 source factory는 변경하지 않았다.
- Serial/parallel 실제 factorized P6 통합 및 취소 **2/2** (`e6301cdb`): 5,040개
  원본·6 locks에서 전체 normalized identities, bitmap, count/hash, raw candidate
  count/digest와 family count가 일치한다. Source backing과 지원 capability를 먼저
  assert한다. 초기 P4 fixture는 Explicit storage라 factorized 경로를 검증하지 못했고,
  P6로 고쳐 실제 capability를 assert했다. CountUnique setter는 objective도 Unique로
  설정하므로 별도 objective 누락을 실패 원인으로 보지 않는다. 기존 equality 검사는
  유지했다.
- Inventory·기하 footprint 재사용 (`fb9ab33a`) **14/14**: inventory 6,
  footprint 3, projection 3, 실제 factorized serial/parallel·취소 2. 실제 15미노
  mixed Full6L witness의 전체 32,768개 subset projection과 graph의 node/edge/pose,
  원본 P1P7P7 product count/witness를 기존 경로와 대조했다.
- Prefix 검사와 통합 (`0fbec64f`) **14/14**: 새 helper 2, 구조·seed·yield·자원 5,
  실제 물리 witness 3, 제품 gate·전체 결과 통합 2, 기존 prefix 회귀 2다. 실제
  Full6L mixed witness의 32,768개 subset과 역순 인덱싱을 모두 보존했다. 4-O
  문제는 raw/filtered × serial/parallel의 전체 identity·key·hash·확률 bitmap·
  대표 경로가 같고, 실제 후보 감소 및 자연 완주 후 raw−emitted를 확인했다.
  큰 음성 탐색 fixture는 처음에 동일 Union operand의 축약 때문에 길어지지 않아
  1건 실패했다. 제품 코드는 유지하고 서로 다른 음성 branch로 fixture를 고친 뒤
  통과했으며 최초 실패 로그도 보존했다.
- `785baa31`에서 inventory 6, footprint 3, projection 3, factorized source 8,
  결과 통합·취소 4도 모두 다시 통과했다. 두 신규 통합 테스트는 앞의 14개와
  중복되므로 독립된 추가 테스트 수로 합산하지 않는다.

Prefix 모드의 `geometry_candidate_family_count`는 여전히 원시 전체 family다.
`packing_candidate_count`는 실제 방출된 후보를 세고 `packing_candidate_domain`으로
영역을 표시한다. 건너뛴 leaf를 방문하지 않은 상태에서 원시 candidate digest를
계산했다고 주장하지 않으며 해당 필드는 미계산으로 표시한다. 모든 내부 branch가
자연 완주하고 final·whole·count-complete·취소/절단 없음이 확인됐을 때만
`geometry_prefix_pruned_candidate_count = raw − emitted`를 checked subtraction으로
보고한다. 검증 단계에서 거절된 emitted 후보는 이 가지치기 수에 포함되지 않는다.

## 7. 재현과 보존

`clearra-core-executor/examples/full6l_bench.rs`를
`--release --features parallel,wasm-stage-profiling`으로 빌드하고
`run --objective unique --profile`로 실행한다. 실제 native Rust PC Core 하네스이며
App UI 검증을 대신했다고 주장하지 않는다. Diagnostic deadline 실행은 명시적으로
진단으로 기록하고 취소를 성공으로 바꾸지 않는다.

원본 JSON·stderr·runtime receipt·고정 바이너리는
`_local/artifacts/full6l-p1p7p7-20261122/`에 보존한다. Compiled source SHA,
binary SHA-256, 실제 workers, 입력·budget, wall time, kernel RSS와 supervisor의
별도 process-group RSS를 기록한다. Rust u64 ID를 JavaScript Number로 다시 쓴
사본을 원본 ID 증거로 사용하지 않는다.

**최종 Full6L 결과, P7P4 재검증과 게시 tree/SHA는 검증 후 갱신한다.**
